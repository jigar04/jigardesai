02 / LLM evaluation & CI/CD

Model Regression Detection System

A CI/CD-style pipeline that runs an LLM feature against a golden dataset whenever a prompt or model changes, detects quality regressions and alerts the team before bad outputs reach users.

The problem

Most teams ship prompt changes blind. Nobody knows whether a new prompt quietly made the feature worse until users complain.

What I built

  • Prompts are versioned YAML files, and the feature under test is a support-email classifier with typed inputs and outputs.
  • A hand-labeled golden dataset with deliberate edge cases (ambiguous, short, typo-filled and mixed-language emails).
  • Async test runner with multi-dimensional scoring: exact category match, LLM-as-judge summary quality, latency and token use.
  • Run-to-run diffing: pass-rate change, per-category change, and the exact cases that flipped from pass to fail, with configurable warning and critical thresholds.
  • HTML diff report, Slack alerts, and slow-drift detection using a rolling average across runs.
  • A GitHub Action runs on pull requests that change prompts, comments the result and blocks merge on critical regressions.

Stack

  • Python
  • OpenAI API
  • Pydantic
  • SQLite
  • GitHub Actions
  • Slack webhooks
  • Docker
